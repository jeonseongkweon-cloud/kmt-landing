# 2026년 회비대장 실제 자료 점검 v1.0

첨부된 2026년 회비대장 원본을 기준으로 자동 점검한 결과다. 이 문서는 이관 전 검증용이며 아직 Supabase에는 아무 데이터도 넣지 않는다.

## 전체 구조
- 회비대장 시트: ㄱ, ㄱ1, ㄱ2, ㅂ, ㅂ1, ㅇ, ㅇ (2), ㅇ(3), ㅈ, ㅊ, ㅎ
- 실제 이름이 입력된 가정 후보: 51가정
- 월별 납부/연장 기재 항목: 47건
- 자동 확인이 어려워 수동확인이 필요한 이름 후보: 3건
  - ㄱ1 / 11번: `우,나,사(15)`
  - ㅇ / 60번: `해찬,정빈(20)`
  - ㅇ (2) / 62번: `윤   겸(4)` (공백 정규화 확인)

## 이름/가정 해석 규칙
- `김민규(19)` → 가정명 김민규 / 현재 기준 납부일 19일
- `김도영,도훈(15)` → 형제 가정 후보 `김도영 · 김도훈` / 기준일 15일
- 첫 학생 성이 있고 뒤 이름이 두 글자인 형제 표기는 같은 성을 붙인 후보를 만들되 CLASS 학생명단과 대조 후 확정한다.
- 이름이 두 글자이거나 3인 이상 쉼표 표기는 자동확정하지 않는다.

## 금액 정규화 규칙
기존 장부가 만원 단위를 축약해서 쓰므로 아래처럼 읽는다.
- `16,5`, `16.5` → 165,000원
- `14,5` → 145,000원
- `11,6` → 116,000원
- `17만` → 170,000원
- `28만` → 280,000원
- `30`, `30만` → 300,000원

금액은 자동 회비 기준으로 쓰지 않고 과거 실제 수납액 기록으로만 이관한다.

## 결제방법 정규화
- `페이`, `페` → 울산페이
- `통장`, `통` → 계좌이체
- `카드`, `카` → 카드
- 그 외 → 확인 필요/기타

## 실제 납부일
월 셀의 `1/8페이`, `3/13페`, `4/9통` 등의 앞 날짜를 실제 납부일로 읽는다.
예: 3월 칸의 `3/13페` → 적용월 2026-03 / 실제납부일 2026-03-13 / 울산페이.

1월 칸에 `12/28통장`, `12/31통장`처럼 전년도 12월 날짜가 있으면 2025-12-28, 2025-12-31로 해석할 수 있으나 최종 이관 전 미리보기에서 확인한다.

## 사진의 수기 표시 반영 규칙
첨부된 종이대장 사진과 운영 설명을 함께 적용한다.
- 사선: 해당 월 회비 대상 아님 (`not_applicable`). 미납 계산에서 제외.
- 금액 동그라미: 단순 확인 표시. 데이터화하지 않음.
- 이름 옆 괄호 숫자: 현재 기준 납부일.
- 기존 괄호 숫자에 사선 후 새 숫자: 납부일 변경. 새 숫자가 현재 기준일이며 과거 숫자는 변경이력으로 보존.
- `연장`: 기준 납부일 변경/연장 확인 대상. 새 날짜는 관리자가 직접 지정.
- 퇴관/이사 등: 이후 월은 `not_applicable`, 과거 수납기록은 보존.

## 절대 자동판단 금지
- 빈칸 = 미납으로 바로 확정하지 않는다.
- 금액을 보고 몇 회분인지 추측하지 않는다.
- 늦게 낸 날짜를 보고 기준 납부일을 변경하지 않는다.
- 가려진 울산페이 이름이 같은 경우 한 가정으로 자동확정하지 않는다.
- 사진에서 불명확한 손글씨를 임의 추정해 금전 데이터로 저장하지 않는다.

## 이관 순서
1. 엑셀 원본 자동 추출
2. CLASS students와 학생명/학생코드/보호자 정보 대조
3. 형제 가정 후보 확인
4. 사진 수기정보를 보정자료로 확인
5. `확정 / 확인필요` 미리보기
6. 관리자가 확인한 자료만 Supabase에 저장

현재 단계에서는 1~5의 설계와 프로토타입만 진행하며 운영 DB는 변경하지 않는다.
